# Лабораторна 1

## Письмові завдання

### Завдання 1

Історично системи використовують різні символи кінця рядка:

- Windows crlf: "\r\n"
- Linux lf: "\n"

Якщо autocrlf не задати тоді git не робить автоматичну конвертацію. Як результат закінчення рядка після зміни файла, зроблена користувачем Linux, буде перероблена повністю користувачем Windows, і буде здаватись ніби змінився весь файл.

### Завдання 2

Різні проєкти можуть вимагати різні версії одного й того самого середовищ

## Задання 3

Приватний ключ ніколи не повинен потрапляти в Git-репозиторій, тому що він є секретом, який дозволяє автентифікуватися від імені власника ключа

Якщо приватний ключ потрапить у репозиторій, навіть якщо репозиторій приватний вважати скомпрометованим.

Дії, якщо вже попав:

- Припинити його подальше використання
- Видалити ключ де він використовується
- Створити нову пару ключів
- Додати новий ключ до сервісу
- Видалити секрет з робочого дерева і поставити в env
- Очистити історію репозиторію(де саме цей ключ був злитий)

### Завдання 5

З'являється:

- Require a pull request, Require 1 approval (Developer A -> PR -> Developer B -> Approve -> merge)
- тести обов'язкові
- заборона навіть адміністраторам обходити встановлені правила

Для solo repository обходження правил адміністратором може бути практичним аварійним механізмом, адже правила все одно діють за замовчуванням, але власник має можливість свідомо їх обійти. Для team repository це вже слабке місце безпеки, так як адміністратор може фактично скасувати весь процес контролю.
